## 2025-03-01 - Disabled Cursor vs Pointer Events None and Icon Button Focus states
**Learning:** Using `pointer-events-none` for disabled states prevents the `not-allowed` cursor from appearing on hover. While replacing it with `cursor-not-allowed` fixes the cursor issue for `<button>` elements, it introduces a major bug for polymorphic components (like shadcn/ui components using Radix's `Slot` or `asChild`) or native `<a>` tags. Native links do not respect the `disabled` attribute directly; `pointer-events-none` is crucial for preventing click events on disabled links.
**Action:** Do not arbitrarily replace `pointer-events-none` with `cursor-not-allowed` in polymorphic design system components. Additionally, always ensure custom icon buttons include robust `focus-visible` styles for keyboard accessibility, as they are easily overlooked.
